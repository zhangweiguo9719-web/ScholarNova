# ScholarNova 真实 API 全流程验收 — 2026-09-08

## 结论与测试范围

本轮实际调用用户本机配置的模型和学术 API，不以 Mock 测试、HTTP 200 或“有回答”替代功能验收。检索、中文翻译、四种分析、PDF 图文分析、知识库、引用问答和研究路线均已跑通相应真实路径；同时发现并修复了目的文件夹不准确、Token 漏算、规划模板回退和错误成功提示等问题。

**仍不能宣称所有能力已经无限制可用。** Semantic Scholar 延迟有波动；下载不到合法全文时仍只能分析摘要；Zotero 本轮保证元数据同步而非 PDF 附件；模型生成的研究方案和图片需要人工核验。下面逐项区分。

测试针对 v1.2.1 之后的当前源码，修复记录在 `Unreleased`。原 v1.2.1 安装包和标签不被覆盖，本报告不是“新安装包已经发布”的声明，也不是 macOS 上真实模型调用的验收。

### 隔离与真实调用方式

- FastAPI 测试客户端执行真实应用端点，使用独立 SQLite、配置副本、上传目录和图像目录；未替换业务处理或伪造模型响应。
- 文字与视觉请求观察器只记录实际网关返回的用量、模型、结果状态和耗时，不修改请求内容或响应。
- 以 12 篇真实检索结果为样本，建立 `QA-20260908-RAG` 分类，保存其中 10 篇。仅一篇执行自动润色；不是对 10 篇各做一次全文精读。
- Zotero 使用独立空白 profile、独立文库与端口做写入测试，不在用户原文库试写。用户原文库测试前后总条目数与版本号未变。
- API Key、配置副本、知识数据、模型原始响应和测试图片留在本机忽略目录，不进入公开仓库。

## 实测发现的缺陷与修复

1. **Zotero 选错目标**：原 Connector `saveItems` 使用 Zotero 当前选中目录，忽略论文里的集合字段。改用独立保存会话、完整层级匹配、`updateSession`，最后回读真实新增条目和集合。同路径歧义、群组库等不确定情况先拒绝；无法确认的写入提示“可能已经保存”，避免盲目重试。
2. **图书馆被代理误判**：只对配置的校园门户，在连接类失败后安全直连重试；各次重定向仍做地址校验，不全局关闭代理，不绕过学校认证。
3. **架构评判没收到原文**：模板把分析原文变成字面的占位符，现已正确插入真实分析。
4. **知识分析漏算 Token**：把二次架构评判的成功/失败已报告用量纳入总数；真实复测 4,028 对 4,028。
5. **润色无效输出被静默忽略**：返回明确的 `completed / invalid_response / model_unavailable / skipped`，保留原文与已发生用量，未调用时不冒充模型成功。
6. **路线图片刷新丢失和假成功**：持久化阶段路线图链接；连接中断、无 done、缺图、规划回退分别提示，不能统一 toast 成功。
7. **路线规划变成通用模板**：两个规划器原先绕过统一路由，受思考输出预算影响，真实调用分别耗尽 1,024 / 1,536 输出 Token 后未产出可用规划。改用统一主备路由和禁思考请求参数；规则回退必须标记。
8. **模型补造公式**：真实复核发现两条未经材料支持的公式。生产过滤器只保留知识材料中原样存在的公式，不能用模型自己的分析作为自证；离线重放删除了两条无依据公式。
9. **离线测试意外外呼风险**：补齐知识分析测试里漏掉的二次架构评判模拟。后续完整回归使用隔离运行目录和非真实模型凭据。

### 研究图质量复核

首次两个 U1 文件都存在、PNG 可读取，应用静态地址均 HTTP 200；但首张含重复/模糊英文标签，阶段图采用了通用模板，因此不以文件存在作为内容质量通过。

修复规划路由后，只复用已有资料做两次文字规划复测，不重复整条链：返回 6 个定制架构模块与 5 个相关研究阶段，无主备失败、无规则骨架，合计 6,198 Token。随后用过滤无依据公式后的计划做一次有界 U1 出图复核，41.2 秒生成成功。图中已有混合检索、生成对齐和可靠性评估等针对本研究的模块，但仍出现重复标题和英文拼写错误，**尚未通过可直接用于论文的图像质量验收**。研究图仍属于待人工核验的建议；可编辑结构化文字/SVG与原文是核验依据，生成图不能独立充当论文证据。

## 用量和效率的口径

- 已记录文字/视觉供应商用量 **51,530 Token**，对应 **22 次完成请求**，包括复测；不是全部平台账单的精确值。
- 另执行 **3 次 U1 生图请求**；应用当前生图响应未归一化文字 Token，不能把图片调用当作免费或 0 消耗。
- 首次查询规划被取消，没有取得供应商用量；本轮发现的一个旧测试曾存在未模拟二次调用的风险，无法据此还原完整账单。因此总计应视为**已记录用量下限**，最终扣费以各供应商账单为准。
- 此处不是 Codex 对话自身 Token；平台没有提供本轮精确 Codex 用量，不编造数字。
- 单次流程样本的耗时不等于 P95 或并发负载能力。本轮没有重新跑 PaSa/Asta 比赛集，不产生新的 F1，也不宣称超过 SPAR。

## 可自行复测的完整案例

1. 设置中选择自己可用的主模型，分别检测文字与视觉任务；研究图指定支持图像生成的模型。不要给不同厂商混用 Key。
2. 搜索 `Retrieval augmented generation for knowledge intensive NLP`；观察各源状态、已耗时、论文标题/摘要/来源。相同查询重新发起应出现新一轮过程。
3. 选择原始 RAG 论文：翻译标题、四种分析分别运行。没有全文时必须标记摘要；切换论文后同搜索会话的分析应保留，开始新搜索后不混入旧分析。
4. 选择带合法 PDF 的论文，执行全文分析；核对材料范围、图表页数，并检查一条实验结论能否在原文找到。上传一份自己有权使用的 PDF 再查状态。
5. 保存论文到一个独立研究分类，至少 10 条；开启一次润色，核对内容确实改变；重新打开应用后分类和内容仍存在。
6. 对该分类做研究分析和推荐，再问智能体相关问题；展开引用核验原材料。再问明显无关问题，检查是否说明缺少证据。
7. 创建研究路线并生成，观察三个阶段，不要只看成功提示；打开图片、刷新路线，确认两图链接仍存在。检查规划来源、公式依据以及图中拼写。
8. 开启 Zotero 本机通信。用测试文件夹保存一篇元数据，在 Zotero 中核对真正落点；当前 PDF 附件仍需另行处理。不要在“可能已写入”后反复点击。
9. 图书馆只验证门户与用户授权访问；不得把可打开门户当作全库下载权限。分区无授权数据应继续显示未知。
