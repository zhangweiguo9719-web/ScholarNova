# v1.2.4：重复帮助回复与模型调用状态修复

## 本次实际问题

在用户的 Windows 安装版对话中核对到：

1. “我该如何使用你”和“那下一步呢”均尝试 Qwen 后失败，应用两次显示同一整段内置指南。
2. “这两次回答咋一样”未被识别为当前使用对话的反馈，再次错误进入科研检索并提示材料不足。
3. 请求计数过去仅在收到正常响应后更新，超时请求仍显示 0；这不能证明没有发出请求，更不能证明免费。

上版仅证明兜底可用，没有满足稳定 AI 连续指导的体验要求。本次不将旧答案改写或删去，便于用户核对。

## 修复范围

- 使用指导仍只尝试当前“智能体”模型一次，等待预算由 12 秒改为 45 秒，输出上限由 800 改为 500 Token。SiliconFlow 的禁思考参数已存在，不将原故障归咎于未关闭思考。
- 当前使用对话中的重复反馈、没看懂、换种说法等进入指导模型，不做论文检索；中间明确切换科研问题后，不沿用旧帮助主题。入口仍是有边界的规则，不声称能理解所有表达。
- 首次可以解释流程；追问只推进下一步，不知道用户进度时先澄清。提示词不再包含容易被复制为论文引用的示例编号。
- 原生复测又发现“道歉后重述步骤”的语义重复，因此追加单轮约束：简短追问和重复反馈先只问一个进度澄清问题，用户回答“我卡在准备论文”“选择来源”等后，再给该阶段的指导。调用状态问题不套用此约束。末尾问号校验只是基本输出检查，不是完整语义判定器。
- 失败改为简短的本地状态和下一步操作，不再复制整段指南；若模型逐字重复上一条回答，也会拦截并保留真实用量。这不保证检测所有语义相近的回答。
- 超时取消会关闭模型客户端，不额外重试。科研问题的真实证据约束保持不变。
- 界面直接展示模型、失败类型、请求与响应状态；中文输入法确认候选词不会触发发送，增加同步防重发保护，当前请求结束前禁止清空或删除该对话。

## 用量口径

| 字段 | 含义 |
| --- | --- |
| request_attempts | 程序进入 SDK/HTTP 请求的次数；不证明服务端已收到 |
| responses_received | 收到正常响应或 HTTP 错误响应的次数 |
| usage_reports | 服务商响应带有用量对象的次数 |
| Token | 服务商已返回的用量，不估算未返回部分 |

没有用量报告时显示未知，而非把 0 当作未调用。历史记录没有这些字段时也明确标注无法确认。

## 用户可复测的最小案例

在一个新对话中依次发送：

1. “我该如何使用你”：应尝试配置的智能体模型，无须先导入论文，成功时显示“AI 使用指导”。
2. “那下一步呢”：应询问你所处的步骤，不再粘贴整篇指南。
3. “我卡在准备论文”：应继续解释准备论文的步骤，不重新要求你选择步骤，也不转成“材料不足”的科研结论。

另可在使用指导的近期上下文中反馈“这两次回答咋一样”。成功时核对模型和三项计数；失败时应显示本地状态、失败类型和未知用量，不将本地提示称作模型回答。科研问答仍需真实材料，且帮助追问仍受有限近期历史和匹配规则的约束，不保证任意表达或无限轮对话均被识别。
