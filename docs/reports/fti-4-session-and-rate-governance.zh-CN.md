# ScholarNova FTI-4：会话、限流与默认模型治理报告

日期：2026-09-03
适用范围：`main` 源码版（v1.1.1 安装包之后的开发版本）

## 阶段结论

本阶段把产品从“能搜索、能问答”推进到更适合普通用户连续使用的状态：Semantic Scholar 的所有内部访问入口共用同一限流节奏与冷却状态；搜索页不再恢复上次历史结果；科研智能体支持文件夹和相互隔离的对话；默认文本模型改为智谱 GLM，同时继续保留 MiMo、Qwen 等可选适配器。

## 完成的改动

### 1. Semantic Scholar 限流治理

- 所有进程和调用入口共用至少 1.25 秒的请求间隔，低于官方 Key 的 1 request/second 上限。
- 搜索、网络检测、健康检测和 PDF 元数据补全统一经过同一个限流器，不再各自绕过节奏控制。
- 收到 HTTP 429 后读取 `Retry-After`，将冷却截止时间写入本机共享状态；后续请求先等待冷却，而不是继续撞限额。
- 最近 5 分钟已有成功请求时，健康检测直接读取本机快照，不额外消耗一次 Semantic Scholar 请求。
- 429 被标记为“数据源可达但正在限流”，不会被误报成 Key 错误或网络断开。
- 保留服务端检索结果缓存，以减少重复 API 调用；它只缓存论文检索响应，不保存用户的搜索对话历史。

官方依据：[Semantic Scholar API](https://www.semanticscholar.org/product/api) 与 [API Tutorial](https://www.semanticscholar.org/product/api/tutorial)。

### 2. 搜索页会话边界

- 搜索状态不再写入浏览器持久化存储。
- 离开搜索页时清除关键词、计划、结果、选中文章和单篇分析临时记录。
- 返回搜索页后显示全新的起始页面。
- 同一次停留中可以重复搜索完全相同的关键词；切换论文时，已经完成的 AI 分析仍会恢复。
- 发起一次新搜索后，上一轮的单篇分析临时记录立即清空。

### 3. 科研智能体文件夹与独立对话

- 新增“研究文件夹”和“新对话”，不同研究方向可以分开管理。
- 每个对话独立保存消息、标题、材料开关和当前文件夹。
- 删除文件夹时不删除对话，而是把对话安全移到“未分类”。
- 删除对话只影响当前本机的该条记录；不会修改知识库或 Zotero。
- 对话仅保存在当前设备，最多保留 80 个对话、每个对话 40 条消息，避免无限增长。

### 4. 模型默认值与兼容性

- 默认主文本模型：`zhipu / glm-5.2`。
- 默认视觉模型：`zhipu / glm-4.6v-flash`。
- 继续支持 MiMo、阿里云百炼 Qwen、硅基流动 Qwen、DeepSeek、Ollama、SenseNova 和自定义 OpenAI-compatible 接口。
- GLM 视觉探针改为标准尺寸 JPEG，并移除智谱接口不需要的 `detail` 字段。
- 真实视觉探针结果：通过；13,938.8 ms；输入 44 Token、输出 4 Token、总计 48 Token。
- 真实文本探针结果：`glm-5.2` 通过；12,724 ms（供应商实时负载会影响延迟）。

智谱视觉请求格式参考：[GLM-4.6V-Flash 官方文档](https://docs.bigmodel.cn/cn/guide/models/free/glm-4.6v-flash) 与 [OpenAI API 兼容说明](https://docs.bigmodel.cn/cn/guide/develop/openai/introduction)。

## 一套完整的用户验收案例

前置条件：已启动 ScholarNova；设置页已保存至少一个文本模型；如需 Semantic Scholar，填入自己的 Key；如需本地文献，先启动 Zotero 并允许本机应用通信。

1. 打开“设置 → 数据源”，点击重新检测。预期：Semantic Scholar 显示可达；即使暂时 429，也应显示限流状态而不是 Key 无效。
2. 打开“设置 → 模型”，确认主模型为 GLM-5.2，点击文本真实能力测试。预期：显示成功、耗时和真实 Token。
3. 在视觉任务选择 GLM-4.6V-Flash，执行视觉能力测试。预期：识别测试图为红色并显示 Token。
4. 打开“搜索”，输入“retrieval augmented generation for scientific literature review”。预期：看到规划阶段、真实来源/API、动态耗时和结构化论文卡片。
5. 不修改关键词再次点击搜索。预期：相同关键词可以重新执行；上游结果缓存可能减少 API 调用和等待。
6. 选择一篇论文执行 AI 分析，再切换到另一篇后切回。预期：本轮已完成分析仍存在。
7. 切换到“知识库”或“智能体”，再回到“搜索”。预期：关键词、结果和分析均已清空。
8. 打开“智能体”，新建“RAG”和“交通预测”两个文件夹，各建一个对话并分别提问。预期：两个对话内容互不串联。
9. 删除一个文件夹。预期：其中对话进入“未分类”，内容没有丢失。
10. 关闭再打开应用。预期：智能体本地对话仍在；搜索页保持空白，不自动恢复旧搜索。

## 已知边界与下一阶段

- Semantic Scholar 的共享治理能显著减少 429，但无法取消上游服务在高峰期的容量限制；单源受限时系统仍应依靠 OpenAlex、Crossref 和 arXiv 返回结果。
- 智能体文件夹目前是单机本地组织，不含账号、多设备同步、团队共享和端到端加密。
- 搜索结果采用“离页即清空”，尚未提供用户主动固定某次搜索为项目资产的功能；需要长期保存时应把论文加入知识库。
- GLM-4.6V-Flash 是默认视觉候选，不代表用户账号在任何时刻都有可用配额；设置页真实能力测试是最终判断。
- 本轮真实 RAG 问答引用覆盖率为 80%，因此系统如实标为“部分覆盖”而不是“已验证”；逐句引证约束与低成本二次修订是下一阶段的重要质量门禁。
- 下一阶段优先补充：可取消/渐进式搜索、搜索结果显式保存为研究项目、对话导出与删除策略、真实用户任务集的延迟和成功率统计。
