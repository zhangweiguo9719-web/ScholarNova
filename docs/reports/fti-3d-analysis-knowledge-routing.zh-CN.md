# FTI-3D 论文分析与知识工作流路由报告

日期：2026-09-02

## 本轮目标

把论文正文分析、知识润色、研究方向分析、研究路线文字生成和推荐规划迁移到统一主备文本模型路由，同时保持 PDF 视觉页与研究架构图的专用模型隔离。

## 已完成

1. 论文正文文本分析使用 analysis 任务主模型；主模型失败后才尝试显式备用文本模型。
2. PDF 图表页面只交给 vision 任务模型。视觉调用失败后，系统明确降级为解析正文、表格和图注，不宣称读取了图片。
3. 论文分析合并记录视觉尝试与文本主备尝试的供应商 Token；主备均失败时仍保留已报告用量。
4. 知识自动润色、研究方向分析和研究路线文字分析使用统一 analysis 路由。
5. 知识分析响应与页面显示实际供应商、模型、是否由备用模型接管及总 Token。
6. 研究路线出图继续走独立 diagram 配置，未接入普通文本备用模型。
7. 推荐规划使用独立 recommendation 任务，并禁止在没有真实学术 API 元数据时虚构题目、作者、DOI 或引用量。
8. 主备文本模型均不可用时，论文、知识分析和推荐返回只依据现有材料的规则结果，不再直接返回 500。

## 明确边界

- 当前论文分析会解析合法获取或用户导入的 PDF，并使用有界、章节优先的正文上下文；尚未实现覆盖超长论文每个分块的 Map-Reduce 分层归纳。
- Token 数来自模型供应商响应；供应商不返回用量时仍会显示 0，系统不会伪造估算值。
- 推荐入口本轮提供“可核验检索方向”，真正论文候选仍必须由 Semantic Scholar、OpenAlex、Crossref 或 arXiv 等检索源返回。
- 本轮没有调用真实模型或出图服务，避免为自动回归测试消耗用户额度。

## 验证结果

- 后端非联网测试：310 项通过，27 项联网测试未执行。
- FTI-3D 相关回归覆盖文本主备路由、视觉任务隔离、Token 记录、模型离线规则兜底和不伪造推荐。
- 前端自动测试：19 项通过。
- TypeScript 类型检查通过。
- 前端生产构建通过，共转换 1531 个模块。
- 本机运行版后端健康检查为 HTTP 200；知识分析页面在深色模式下正常加载。
- 本轮自动测试和页面验收未发起真实模型请求，产品 API Token 消耗为 0。

## 下一阶段

优先增加用户主动触发的真实模型能力探针：分别验证文本、结构化输出、视觉、出图、Embedding 与工具调用，并把结果与测试时间保存在本机。完成后进入快速搜索与深度研究的预算模式拆分。
