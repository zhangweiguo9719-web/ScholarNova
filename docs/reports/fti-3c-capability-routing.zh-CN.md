# FTI-3C 模型能力与文本任务路由报告

日期：2026-09-02

## 本轮目标

在不改变论文视觉分析、SenseNova 出图和业务数据结构的前提下，让用户在配置模型时提前看到任务能力匹配情况，并把查询规划与翻译接入上一阶段的显式主备文本路由。

## 已完成

1. 新增保守能力注册表：文本、结构化输出、视觉理解、图像生成、Embedding。
2. 新增本机能力检查接口；只分析提供商与模型名，不访问供应商、不产生 Token。
3. 设置页按任务展示能力徽标及“匹配 / 不匹配 / 未知”提示。
4. AI 查询规划改用主模型与显式备用模型；全部失败时继续使用原有规则规划。
   每条模型路线最多占用 5.5 秒，确保 12 秒总规划预算内备用模型仍有接管机会。
5. 标题/摘要翻译改用同一主备路由，响应记录实际模型、主备状态和 Token。
6. 修复调试环境 localhost Ollama HTTP 被静态协议表提前拒绝的问题，外部地址安全策略不变。

## 明确边界

- 模型能力由已知模型命名规则保守推断，不等同于一次真实多模态或结构化输出测试。
- 自定义 OpenAI-compatible 接口的视觉、出图和 Embedding 能力显示“未知”，避免误报。
- 论文长文分析和知识推荐尚未迁移到主备文本路由。
- 视觉分析与 SenseNova 出图继续使用独立任务配置，不会错误调用普通文本备用模型。

## 验证结果

- 后端非联网测试：305 项通过，27 项联网测试未执行。
- 本轮针对性测试：74 项通过。
- 前端自动测试：19 项通过。
- TypeScript 类型检查通过。
- 前端生产构建通过，共转换 1531 个模块。
- 本轮自动测试未调用真实模型，产品 API Token 消耗为 0。

## 下一阶段

优先把论文长文分析与知识推荐迁移到统一路由，同时保留全文分块、视觉任务隔离和确定性结果；随后增加可选的真实能力探针，再进入快速/深度检索预算模式。
