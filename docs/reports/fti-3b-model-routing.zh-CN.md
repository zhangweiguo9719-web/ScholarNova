# FTI-3B 多模型主备路由优化报告

日期：2026-09-02

## 本次目标

让 ScholarNova 在继续支持智谱、MiMo、DeepSeek、Ollama 等模型的同时，可以安全接入阿里云百炼 Qwen，并在主文本模型不可用时执行一次明确、可观察、可计量的备用调用。

## 已完成

- 设置页新增“备用文本模型”，默认关闭，不会造成常态双调用。
- 备用路线当前接入科研问答，不介入视觉分析与 SenseNova 出图；统一路由契约已为后续分析、查询规划、翻译和推荐迁移预留任务类型。
- 主模型经过有限重试仍失败后，系统才尝试一次备用模型；主备均失败时返回带来源编号的确定性检索证据。
- 智能体响应记录每次尝试的角色、供应商、模型、状态、请求次数和供应商返回的 Token，并显示实际接管模型。
- 修复跨供应商凭据继承：Qwen、智谱、MiMo 等任务模型不会误用另一家供应商的 Key、Base URL 或默认模型。
- 修复任务级 Anthropic 与 Ollama 配置未完整采用独立模型和地址的问题。
- API 返回配置时只暴露“Key 是否已配置”，不返回明文；页面本地持久化同样清除主模型、任务模型、备用模型和 Embedding Key。

## 当前边界

- 当前主备路由首先落地在科研问答生成链，统一路由服务已经可供其余文本任务逐步迁移。
- 引用校验验证的是来源编号与事实句覆盖，不等同于语义蕴含判断。
- Qwen 模型名允许用户直接填写，以兼容后续百炼新增模型；预置值只作为开箱提示，不限制实际模型选择。
